# Data Dictionary

## Transactions Table

| Field Name        | Data Type | Description                                            |
|-------------------|-----------|--------------------------------------------------------|
| transaction_id    | BIGINT    | Unique identifier for each transaction                 |
| user_id           | BIGINT    | Identifier of the user associated with the transaction |
| merchant_id       | BIGINT    | Identifier of the merchant for the transaction         |
| transaction_date  | TIMESTAMP | Date and time when the transaction occurred            |
| amount            | DECIMAL   | Transaction amount in the specified currency           |
| currency          | VARCHAR   | Currency code (USD, EUR, GBP, JPY)                    |
| status            | VARCHAR   | Transaction status: approved, declined, reversed, pending |
| is_international  | BOOLEAN   | Whether the transaction crosses country borders        |
| is_online         | BOOLEAN   | Whether the transaction was made online                |
| fraud             | BOOLEAN   | Ground-truth fraud label (1 = fraudulent)              |

## Users Table

| Field Name | Data Type | Description                                            |
|------------|-----------|--------------------------------------------------------|
| user_id    | BIGINT    | Unique identifier for each user                        |
| user_name  | VARCHAR   | Name of the user                                       |
| email      | VARCHAR   | Email address of the user                              |
| phone      | VARCHAR   | Phone number of the user                               |
| created_at | TIMESTAMP | Timestamp indicating when the user account was created |

## Engineered Features

Generated by `add_transaction_features()` in `transaction_features.py`.

### Per-User Features

| Feature Name              | Data Type | Description |
|---------------------------|-----------|-------------|
| user_time_since_last_txn  | FLOAT     | Seconds since the user's previous transaction |
| user_amount_zscore        | FLOAT     | Z-score of amount vs user's expanding mean/std (`shift(1)`, `ddof=1`) |
| user_txn_count_{window}   | FLOAT     | Count of user transactions in rolling window |
| user_amount_sum_{window}  | FLOAT     | Sum of user amounts in rolling window |
| user_amount_mean_{window} | FLOAT     | Mean of user amounts in rolling window |

### Per-Merchant Features

| Feature Name                   | Data Type | Description |
|--------------------------------|-----------|-------------|
| merchant_txn_count_{window}    | FLOAT     | Count of merchant transactions in rolling window |
| merchant_amount_mean_{window}  | FLOAT     | Mean merchant amount in rolling window |
| merchant_fraud_rate_{window}   | FLOAT     | Rolling fraud rate for the merchant |

### Per-Currency Features

| Feature Name                | Data Type | Description |
|-----------------------------|-----------|-------------|
| currency_txn_count_{window} | FLOAT     | Count of transactions in this currency per window |

### Per-Status Features

| Feature Name              | Data Type | Description |
|---------------------------|-----------|-------------|
| status_txn_count_{window} | FLOAT     | Count of transactions with this status per window |

Default rolling windows: `1h`, `24h`, `7d`, `30d`.

## Data Leakage Prevention

- All rolling aggregations use `closed="left"` to exclude the current transaction
- Z-score uses expanding window with `shift(1)` to exclude current value
- Sample standard deviation (`ddof=1`) instead of population standard deviation
- Division by zero handled explicitly (returns NaN when std=0)
- Time-based splitting enforced when temporal features are present

## Synthetic Data Statistics

The included `synthetic_fraud_data.py` generates:
- 5,000 transactions over 60 days
- ~7% fraud rate (356 fraudulent)
